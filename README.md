# Haptic 🚀

**A Telegram automation DSL that transpiles to Node.js.**

Haptic is a domain-specific language (DSL) built for Telegram bots and userbots. It compiles directly to JavaScript, supports native Telegram-oriented syntax, and still allows you to write raw Node.js code whenever needed.

Tip:  If you are indonesian read README.ID.md
The goal is simple:

> Write Telegram automation, not framework boilerplate.

---

## Why Haptic?

Most Telegram projects eventually end up with:

* Framework-specific handlers
* Middleware chains
* Configuration files everywhere
* Repetitive command registration
* Boilerplate event routing

Haptic provides a higher-level syntax designed specifically for Telegram automation while keeping full access to the JavaScript ecosystem.

### Example

```haptic
bot "ExampleBot":
 token = env("BOT_TOKEN")
end

command start:
 reply "Hello World"
end

on message match /ping/i:
 reply "pong"
end
```

# Installation

## Global Install

```bash
npm i -g https://github.com/HexZoNetwork/Haptic-Streo/releases/download/Haptic/haptic-streo-0.1.0.tgz
```

Verify installation:

```bash
haptic --help
```

Create a new bot project:

```bash
haptic new bot mybot
cd mybot
```

Projects generated by `new` and `wizard` automatically include a local compiler binary at:

```text
.haptic/bin/haptic.cjs
```

This means commands like:

```bash
npm run build
npm run run
npm run dev
npm run doctor
```

do not depend on a global installation.

---

## Direct Execution

Run a Haptic file directly:

```bash
haptic bot.haptic
```

---

## Local Development Install

If you'd rather avoid a global installation:

```bash
npm i -D https://github.com/HexZoNetwork/Haptic-Streo/releases/download/Haptic/haptic-streo-0.1.0.tgz
```

Then use:

```bash
npx haptic --help
```

# JavaScript → Haptic Transformation

Convert JavaScript source files into Haptic:

```bash
haptic transform bot.js
```

Or transform an entire project:

```bash
haptic transform .
```

### Default Behavior

The transformer:

* Scans `.js`, `.mjs`, and `.cjs`
* Skips hidden directories
* Skips `node_modules`
* Generates `.haptic` files beside original sources
* Synchronizes JS entry points with `config.hpconf`
* Synchronizes dependencies and scripts from `package.json` when supported by the selected engine

# Language Features

## Supported Syntax

### Telegram Constructs

* `bot`
* `userbot`
* `command`
* `on message`
* `on command`

### Control Flow

* `if`
* `else`
* `else if`
* `elseif`
* `elif`
* `for in`
* `try`
* `catch`
* `return`
* `stop`

### Functions

* `func`
* `fn`

### Variables

* `let`
* `const`
* `var`

### Data Queries

* `select`
* `select ... into`
* `insert`
* `update ... where ...`
* `delete from ... where ...`

### DSL Operators

* `and`
* `or`
* `not`
* `is`
* `is not`
* `nil`

### Mixed Syntax

Raw JavaScript can be embedded directly inside DSL blocks.

### Compile-Time Validation

Expressions are validated during compilation, allowing many syntax mistakes to be detected before runtime.

# Configuration

Default configuration file:

```text
config.hpconf
```

JSON format:

```json
{
  "entry": "bot.haptic",
  "engine": "telegraf",
  "outDir": "dist",
  "cacheDir": ".hpcache",
  "runtimeMode": "jit",
  "profile": "testing",
  "plugins": []
}
```

INI-style syntax is also supported:

```ini
entry = "bot.haptic"
engine = "telegraf"
profile = "testing"
cacheDir = ".hpcache"
```

# Security

Before publishing your project:

* Never commit real credentials
* Use `.env.testing.example` as a template
* Keep `.env*` files excluded from Git
* Keep secrets outside source control

# Philosophy

Haptic isn't trying to replace JavaScript.

JavaScript remains the runtime.

Haptic exists to make Telegram automation easier to write, easier to read, and easier to maintain.

Focus on the automation.

Let the compiler handle the plumbing.
